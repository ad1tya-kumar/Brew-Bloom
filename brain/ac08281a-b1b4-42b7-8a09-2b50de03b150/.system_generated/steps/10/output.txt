Tailwind CSS v4 introduces a fundamental architectural shift, moving from a JavaScript-based configuration to a **CSS-first approach**[1][2][3]. Below are the key breaking changes and "gotchas" to watch for when upgrading a Vite project.

### 1. Configuration: Goodbye `tailwind.config.js`
In v4, `tailwind.config.js` is no longer required[4][5]. Instead, you define your theme and customizations directly in your CSS using the `@theme` directive[1][6][3].
*   **The `@theme` Block:** This replaces `theme.extend`[5][2].
    ```css
    @import "tailwindcss";

    @theme {
      --color-brand: #3b82f6;
      --font-display: "Inter", sans-serif;
    }
    ```
*   **Automatic Content Detection:** v4 automatically scans your project for template files[6][5][3]. You no longer need to maintain the `content` array in a config file[6][7]. If Tailwind misses files, use the `@source` directive in your CSS to specify them[5][8].

### 2. Vite Integration Changes
If you were using the PostCSS plugin in v3, you should migrate to the new official Vite plugin for better performance[9][6].
*   **Installation:** Install `tailwindcss` and `@tailwindcss/vite`[10][7].
*   **Vite Config:** Update your `vite.config.ts`:
    ```typescript
    import { defineConfig } from 'vite';
    import tailwindcss from '@tailwindcss/vite';

    export default defineConfig({
      plugins: [tailwindcss()],
    });
    ```
*   **Imports:** Replace the old `@tailwind base;`, `@tailwind components;`, and `@tailwind utilities;` directives with a single CSS import[9][6][7]:
    ```css
    @import "tailwindcss";
    ```

### 3. Key "Gotchas" & Breaking Changes
*   **Utility Renames:** Some utilities have been renamed, which can break your UI[5]. Examples include `shadow-sm` becoming `shadow-xs` and `outline-none` becoming `outline-hidden`[5][11].
*   **Browser Support:** v4 targets modern browsers only (Safari 16.4+, Chrome 111+, Firefox 128+)[9][12]. It relies on modern features like `@property` and `color-mix()`[9][12].
*   **Preflight/Defaults:** Some default styles (like heading sizes or button resets) may appear different due to changes in how Preflight is handled[13][14].
*   **Plugin Compatibility:** Check if your third-party Tailwind plugins support v4[15][16]. Some v3 plugins may need updates or may no longer be necessary (e.g., container queries are now in core)[1][17].

### 4. Migration Strategy
*   **Use the Upgrade Tool:** Do not attempt to migrate manually if possible. Run the official codemod:
    ```bash
    npx @tailwindcss/upgrade
    ```
*   **Work on a Branch:** Run this on a clean Git branch so you can easily compare changes[5][18][11].
*   **Review the Diff:** The tool automates most of the work, but you should manually inspect your CSS and components for layout shifts, especially regarding spacing and border defaults[5][18][11].
