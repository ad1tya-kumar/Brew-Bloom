To implement OTP authentication using `supabase-js`, you use `signInWithOtp` to initiate the process and `verifyOtp` to complete the authentication[1][2][3].

### 1. Initiating the OTP Flow
Use `supabase.auth.signInWithOtp` to send a one-time password to the user's email or phone number[1][4].

**Email Example:**
```javascript
const { data, error } = await supabase.auth.signInWithOtp({
  email: 'example@email.com',
  options: {
    emailRedirectTo: 'https://example.com/welcome', // Optional
  },
})
```

**Phone Example:**
```javascript
const { data, error } = await supabase.auth.signInWithOtp({
  phone: '+13334445555',
})
```

---

### 2. Verifying the OTP
Once the user receives the code (via email or SMS), use `supabase.auth.verifyOtp` to confirm the token and sign the user in[5][2][3].

```javascript
const {
  data: { session },
  error,
} = await supabase.auth.verifyOtp({
  email: 'example@email.com',
  token: '123456',
  type: 'email', // Use 'sms' if verifying a phone OTP
})
```

### Key Parameters for `verifyOtp`
*   **`type`**: Must match the verification type (`'email'`, `'sms'`, or `'phone'`)[5][6][7].
*   **`token`**: The 6-digit code received by the user[7][8].
*   **`email` / `phone`**: The identifier used during the `signInWithOtp` step[5][6].

### Important Notes
*   **Automatic Signup**: By default, `signInWithOtp` may create a user record[9]. If you want to prevent this, check the `shouldCreateUser` option in the official Supabase documentation for your specific use case[9].
*   **Reauthentication**: If you are using OTP for reauthentication (e.g., changing a password), the flow is slightly different; you typically use `supabase.auth.updateUser` with the `nonce` parameter rather than a standard `verifyOtp` call[7][10].
